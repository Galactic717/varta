# VARTA v2 — план перебудови (2026-10-25)

## Чому переписано з нуля

v1 (`_old_v1/`, 12.5k рядків) мала три системні проблеми:

1. **ШІ робив не ту роботу.** Qwen3-0.6B з LoRA мав *прогнозувати* рух цілей словами (Jev) і *писати* текст з
   блоку фактів. Мовна модель на 0.6B рахує координати гірше за 20 рядків геометрії, а генерація тексту — це
   єдине місце, де може зʼявитися вигаданий факт. Навчання не було завершено, результатів, які б доводили
   перевагу над фізикою, не було.
2. **Інфраструктура для неіснуючих користувачів:** диспетчер на 1000 юзерів, HMAC-посилання, SQLite-схема на
   900 рядків — під ботів, яких немає.
3. **Карта не схожа на NEPTUN.**

## Принцип v2: «модель розуміє питання, код рахує відповідь»

```
питання ──► розбір (модель-класифікатор наміру + детерміновані слоти) ──► Query
                                                                          │
Situation (NEPTUN + MAPA, свіжість, тривоги) ──► виконання Query кодом ──► Facts ──► шаблон UA ──► відповідь
```

* Модель **ніколи не бачить даних** і не генерує текст відповіді → вигадати число чи місто вона фізично не може.
* Слоти (тип цілі, місто, радіус, хвилини) — тільки з газетира/лексикону/регексів; місто, якого немає в
  газетирі OSM, у запит не потрапляє.
* Кожне число у відповіді береться з Facts; тест перевіряє це властивістю.

## Модель

Задача моделі — класифікація наміру (≈12 класів) коротких українських питань. Це NLU-задача, для неї
стандарт — енкодер, а не генеративна LLM. Вибір — **за вимірюванням**, не за вірою: bake-off на окремому
наборі питань, написаних людською мовою (з помилками, суржиком, без шаблонів генератора):

| кандидат | що це |
|---|---|
| правила | ключові слова |
| char-n-gram + LogReg | класичний ML, CPU, мілісекунди |
| multilingual-MiniLM-L12 + LogReg | готовий мультимовний енкодер (у кеші) |
| mmBERT-small (JHU, 2025) fine-tune | сучасний мультимовний енкодер 140M, MIT |
| Qwen3.5-0.8B-Base few-shot | генеративна LLM як класифікатор (для порівняння) |
| GPT-2 small few-shot | щоб перевірити ідею користувача чесно |

У продукт іде переможець за точністю на людському наборі з урахуванням затримки.

## Ядро

* `varta/geo.py` — гаверсинус, азимут, dead-reckoning (як у SDK NEPTUN), CPA/ETA, ймовірність пролету в радіусі.
* `varta/regions.py` — райони/області (point-in-polygon), контур України.
* `varta/gazetteer.py` — населені пункти OSM з відмінками («у Києві», «на Бровари», «біля Кривого Рогу»).
* `varta/sources.py` — NEPTUN WS (+REST-фолбек, тривоги), MAPA.UA `/current`.
* `varta/situation.py` — треки, злиття NEPTUN↔MAPA, свіжість, тривоги, журнал подій (наш власний архів).
* `varta/qa/` — розбір, виконання, шаблони.
* `varta/server.py` — aiohttp: карта, `/api/state`, `/api/ask`, `/api/places`, `/api/assess`.

alerts.in.ua `/llm` прибрано: NEPTUN `/api/v1/alerts` дає ті самі офіційні тривоги структуровано (район,
рівень red/yellow, причина), а парсер markdown-звіту був крихким дублем.

## Карта (як NEPTUN)

Супутник Esri (яскравість ≤0.46, насиченість −0.19) + OpenFreeMap (вода, межі, підписи) + рельєф;
затемнення світу поза Україною; райони під тривогою червоні/жовті (28 %); білі силуети цілей з темним
контуром, поворот за курсом, сліди з градієнтом; скляні панелі (blur 22 px) — «Обстановка», чипи типів,
список по областях, картка цілі. Свої іконки (SVG), не копії NEPTUN. Видимі посилання на NEPTUN і MAPA.UA
(умова їхніх API).

Плюс те, чого в NEPTUN немає: «Мої місця» з радіусом, оцінка для місця, чат з агентом.

## Не в цій ітерації

Telegram/Discord (свідомо), push-сповіщення поза браузером, калібрування прогнозу на архіві (інструмент є,
фіча — після накопичення власного журналу).
